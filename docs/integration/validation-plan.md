# 国服授权与接口联调清单

所有项目当前均待真实账号验证，公开元数据抓取已完成。不要把下表误作测试通过记录。

用户指定登录交互见 [EIMS 参考方案](../design/login-flow.md)。手动粘贴回调网址也必须验证 state、应用身份与角色，不自动等于已取得可持续刷新凭据。

## P0：独立应用授权闭环

1. 确认国服自有开发者应用申请方式，取得自己的 client_id，注册自己的 HTTPS callback，确认军团 scopes 可申请。无需在对话或仓库提供密码/令牌。
2. 采用系统浏览器跳转官方授权页面，用户自行登录并选择角色。Java 保存一次性 state 和 PKCE verifier，回调核验 state，再从后端换取令牌。是否需 secret 以注册应用类型为准。
3. 按国服 metadata/JWKS 验证签名、允许算法、issuer、aud、exp、主体和 scopes。发现 JWT 声明差异时记录脱敏结构，不绕过校验。
4. 获取角色公开所属军团与角色权限。CEO 可结合军团公开 ceo_id 识别，实际资源访问仍需权限验证；不因 UI 标签“总监”就跳过检查。
5. 验证 refresh_token 是否返回、有效期、刷新后轮转、撤销后行为；验证重启后可继续同步。PKCE 元数据支持不等于已完成该流程测试。

## P1：按能力逐个验证

公开军团资料 → 成员名单 → 军团资产 → 建筑 → 拉矿计划 → 观察者 → 观察者账本 → 成员追踪。每个接口保存私有脱敏验收记录：时间、host、固定路径版本、status、scope 集合、实际角色、分页/缓存头、字段存在性、缺失字段、空数据说明。

角色与 scopes 应按模块最小化申请。所需 scope 从 docs/research/api-matrix.md 读取；基本成员名单只要求该军团成员，而资产/追踪需要 Director。月矿计划要求 Station_Manager，账本要求 Accountant，不能因为 scope 相同就当成相同资格。

## 数据一致性

- 按每个接口的 X-Pages/page、from_id 或实际契约分页。每页 ETag 独立；混合 200/304 时须存在正确旧页。变动中的全量快照记录一致性局限，必要时受限重抓；只有完整批次可替换可见数据。
- 尊重国服 Cache-Control、ETag 及实际响应，契约缓存秒数只作为默认计划参考。国际服的新兼容日期/事件缓存不自动启用在国服。
- 401：最多一次受控刷新再重试；403：区分 scope、角色和对象可见性，暂停相关能力并提示；404 不一律解释成对象被摧毁；420/429：按服务响应退避；5xx/网络错误：有限重试和抖动，保留旧数据。
- 支持 X-Esi-Error-Limit-Remain / Reset 等实际返回头，错误预算按服务/IP合理协调，避免把失败重试放大。分页并发初始保守，后续以观测数据调整。
- 空数组、权限错误、暂时失败、未授权、过期快照在页面上必须区分。
- 矿账重复抓取按键 upsert；当前归属不覆盖历史 recorded_corporation_id。资产容器树防循环、未知父节点保留；历史快照差异不是物资流转证据。

## 完成条件

自己的国服应用成功授权与刷新；至少资产、建筑、矿账各取得真实成功响应（军团没有对象时记录成功空响应，另用虚构样例验证界面）；分页与缓存正确；撤销后停止同步；无令牌进浏览器/日志；跨军团访问拒绝。达到后才进入完整页面开发与部署。
