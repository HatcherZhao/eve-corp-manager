# 国服登录方案：参考 EIMS 的分步授权与回调网址导入

状态：用户指定的交互参考，2026-09-06；尚未实现、尚未用真实角色验证。

参考地址：https://eims.games/login 。用户提供的截图可直接观察到下述流程；本次网页检索只取得导航内容，没有取得其客户端授权代码。因此不声称已经验证 EIMS 的 client_id、grant type、state、令牌刷新或后端实现。

## 用户流程

1. 展示本站实际隐私说明，用户同意后开始操作。
2. 可选“切换账号/重新登录”：必要时在独立窗口处理网易登录会话。截图称此操作为“清除缓存”，本项目不要暗示能清除浏览器全部缓存，也不能把任何错误页面都当作成功。
3. 点击“前往网易授权”，在官方页面登录、选择要绑定的角色并授权。本系统不收集网易账号密码。
4. 如果不能自动回到本站，提示用户复制授权完成后页面的完整网址，在本站“授权结果网址”输入框中粘贴。
5. 点击“验证并登录”，验证返回结果，展示角色、所属军团及可用模块；CEO/总监等授权资格根据接口实际响应确认。
6. 成功后清空输入框，建立本站会话并进入工作台；失败则说明过期、角色不符、缺权限或格式错误，并给出重新授权入口。

首版保留这种分步引导与手动粘贴方案。若独立应用支持正常回调，则自动完成同一验证步骤，手动粘贴作为兼容入口。手动粘贴是授权结果的传输方式，不等于某一种 OAuth grant，也不自动解决应用注册问题。

## 待验证的授权模式

| 返回内容 | 处理方式 | 限制 |
|---|---|---|
| query 中的 code + state | 后端核验当前登录事务并换取 token；如该事务使用 PKCE，必须匹配本站保存的 verifier | code 绑定原应用和 callback，不能拿别的应用 code 直接换 token |
| fragment 中的 access_token 等 | 只有明确支持的兼容模式才解析；后端按预期发行者、受众及角色验证，且要求与本站创建的事务绑定 | URL fragment 不会自动发送到服务器；不能声称这种短期 token 可长期后台刷新 |
| 错误回调或非预期格式 | 展示可操作错误并重新授权 | 不能仅凭网址包含 token/code 字样认定登录成功 |

国服 metadata 已声明 code、token 和 S256；EIMS 具体使用哪种模式不能仅凭截图推断。先核实实际授权链接、应用身份和允许的使用方式，再确定兼容实现。不得通过任意 token 导入绕过受众检查。

## 验证与数据处理

- 登录前由本站生成高熵、短期、一次性 state，绑定当前浏览器会话；按实际流程保存 nonce/PKCE verifier。手动粘贴同样要匹配原事务，防止登录到别人指定的角色。
- 使用标准 URL 解析器；限制输入长度，检查预配置的 scheme/host/path、重复参数、error 与 code/token 冲突。不要直接访问用户粘贴的网址，不进行任意 URL 抓取或服务端跳转。
- 回调网址可能携带凭据，不放在 GET 请求、页面分析、错误日志、截图、工单、localStorage 或仓库中；经 HTTPS POST 提交并立即清空。不要把实际回调网址发到公开 GitHub。
- 后端验证 JWT 签名、国服 issuer、预期 aud、有效期与 scopes；不能只解析角色 ID 就登录。无法验证的返回拒绝使用。
- 数据源能力分为“仅本次访问”“支持持续同步”“需重新授权”。没有有效 refresh_token 时，界面明确显示过期后需再次登录，不承诺无人值守同步。
- 独立应用注册是首选路径；若国服确实未开放注册，记录支持的替代接入机制和限制，再决定是否只做手动短期访问。不能因 EIMS 可登录就推断任何项目都可复用其 client_id 或 refresh_token。

## 首版交互建议

采用清晰的单列步骤卡片：授权说明 → 前往官方登录 → 粘贴授权结果 → 验证角色。输入框旁解释从哪里复制、过期如何处理。成功页显示角色/军团和资产、建筑、月矿、人员各模块授权情况；只有账号切换失败时才出现重新登录帮助。不要照搬截图中的“网易并未开放 API”作为当前事实：本项目已经取得国服公开 API 契约，尚未确认的是独立开发者应用注册政策。

## 验收

正常手动粘贴成功；自动回调成功（若支持）；错误/过期/重放 state 拒绝；非本站事务拒绝；错误受众 token 拒绝；无刷新令牌正确降级；粘贴任意 URL 不触发网络抓取；缺少总监权限时按模块限制；日志无 code/token/完整回调网址。实际 EIMS 授权链接和国服真实账号联调完成前，不把本文件视为已验证实现。
