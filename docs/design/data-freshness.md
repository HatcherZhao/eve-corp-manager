# 动态数据新鲜度

## 目标与边界

动态行情和业务快照以三十分钟为本地新鲜度目标，邮件每半小时检查。官方 `Expires`、全局冷却和失败退避仍然优先，不能为了达标提前重复抓取。某些军团接口官方缓存期约一小时，因此不能承诺所有数据严格实时；超过目标时必须明确提示旧数据。

静态物品资料、官网文章发布时间、历史日线、长期矿种比例档案、已保存工业估算和已确认计划不是实时快照，不因这项目标每半小时重新导入或重算。

## 调度

| 数据或机制 | 默认策略 |
| --- | --- |
| 吉他完整订单簿 | 完成本轮后等待十五分钟，并尊重各页官方缓存期限 |
| 市场调度检查 | 每分钟仅检查共享 Redis 门禁；未到期不访问 ESI |
| 市场报价及订单详情过期提示 | 最近成功快照超过三十分钟即过期 |
| 军团资产、建筑、成员、月矿排期、采矿账本 | 三十分钟目标，与官方缓存期限取较晚者 |
| 邮件头与游戏通知 | 每三十分钟检查，与官方缓存期限取较晚者 |
| 业务任务扫描 | 每分钟，单轮最多顺序执行三个任务 |
| 定时任务线程池 | 默认四线程，避免完整市场分页阻塞其他定时任务 |
| 真实上游请求 | 继续使用全实例共享的三秒最小间隔、缓存、ETag、限流冷却和退避 |

市场完整分页本身需要时间，因此十五分钟是两轮之间的等待时间，不是每十五分钟内一定完成一次。接口失败、官方缓存或分页耗时导致超过三十分钟时只展示最后完整快照和过期提示，不发布半轮数据，不绕过限流。

抓取前先写入共享周期预留，写入失败不发起本轮工作；完成后的门禁更新瞬时失败时保留此前预留，避免下一分钟重复整轮同步。每个官方响应页仍独立缓存并遵守 `Expires`，不能因调度门禁失效而提前请求未过期页面。

`EVE_MARKET_ORDER_SYNC_INTERVAL`、`EVE_MARKET_ORDER_SYNC_SCAN_INTERVAL`、`EVE_MARKET_QUOTE_REFRESH_INTERVAL`、`EVE_MARKET_DETAIL_REFRESH_INTERVAL` 可覆盖市场默认策略。定时线程池支持 `SPRING_TASK_SCHEDULING_POOL_SIZE` 覆盖。生产已有显式配置时应先核对，不能仅根据代码默认值推断实际值。

## 已有任务

周期缩短后，发现扫描仅提前健康的 `PENDING` 任务：有最近完成时间、没有失败或租约，并且能证明上游缓存下限。新的执行时间不早于最近完成时间加配置周期、任务冷却、军团同步状态中来源过期时间的最大值。

重排使用数据库条件更新核对原完成时间、原排期和原冷却，不能覆盖运行中、暂停、失败退避或其他实例已经更新的任务。旧版个人通信任务若缺少足以证明缓存下限的记录，保留原排期，下一次成功后自然采用新周期。手动同步成功也保留官方过期时间作为冷却下限。

不手工批量清空调度状态，不解除官方冷却，不直接修改历史业务时间或已有 Liquibase changeset。

## 时间口径

生产 API 的 JVM 为北京时间。现有市场和工业等部分业务通过本地 `LocalDateTime.now()` 保存北京时间，而游戏事件、军团同步及官方响应的时间多为 UTC。MCP 必须逐字段匹配已有存储口径，不能统一加八小时或统一改写数据库。

已确认并修正的北京时间字段：

- `market`：`sourceUpdatedAt`、`quoteSynchronizedAt`、`detailSynchronizedAt`。
- `corporation.lastSyncedAt`、`characters.joinedAt`、`character_role_snapshots.capturedAt`。
- `industry_opportunities.calculatedAt`、`industry_plans.confirmedAt`。
- `industry_market_snapshots.capturedAt/sourceUpdatedAt`、`industry_system_snapshots.capturedAt`。
- `industry_system_cost_index.fetchedAt`、两类静态资料的 `sourceUpdatedAt`、`news.publishedAt`。

邮件发送、月矿到达、同步健康记录、资产同步、拓扑同步等明确的 UTC 字段保持原口径。尚无明确写入来源的工业步骤时间和旧订单报告时间不猜测修改。

例如存储为北京时间 `2026-10-25 22:07:18` 的市场快照，MCP 应输出 `2026-10-25T22:07:18+08:00`，不能再次转换成次日 `06:07:18+08:00`。带 `Z` 的同一瞬时筛选也要转换为该字段实际使用的数据库时间。

## 状态解释

业务快照超过三十分钟，即使官方缓存尚未到期，也显示 `STALE`；这不代表可以立即绕过缓存重新同步。保留 `sourceExpiresAt` 让客户端了解上游允许的下次时间。最近失败晚于最近成功时显示同步失败，缺少成功快照时显示无数据。

机器人回答应同时给出实际更新时间与查询范围。MCP 查询和聚合额外返回 `queriedAt`，供机器人使用服务端当前时刻判断快照年龄；该字段不是同步时间，不能代替业务字段。旧的 `failureCode` 不能单独证明当前仍在失败，应比较最近失败和成功时间。用户查询只读取本站缓存，不触发 ESI，技能也不赋予刷新或写入权限。
