# 军团派生身份统一授权

## 问题与目标

历史迁移只给执行时存在的军团角色写入菜单，新注册军团仍使用旧的 Java 菜单 ID 模板，导致总监身份正确但菜单缺失、建筑/月矿/采矿查看接口返回 403。排查时原军团管理角色有 68 项有效授权，新军团只有 8 项。

目标是让已有军团、新注册军团和以后发布的功能都读取同一份授权定义，注册时间不影响权限。

## 授权机制

`058_derived_role_policy.sql` 创建全局 `eve_derived_role_menu(role_code, menu_id)`，定义 CEO、总监和普通成员各自的功能范围。该表不包含用户、租户或游戏授权数据。

统一视图 `eve_effective_role_menu(tenant_id, role_id, menu_id)` 计算最终有效授权：

- CEO/总监/成员依据角色编码读取全局定义，并受当前军团套餐、套餐状态、菜单状态限制。
- 自定义业务角色继续使用本军团的 `sys_role_menu`，角色与关联记录的租户 ID 必须一致。
- 派生角色的历史菜单复制数据不参与计算；用户仍须拥有从真实游戏身份派生的角色，不能借全局定义取得其他身份。

动态菜单、接口权限、角色菜单 ID 和 Agent 权限摘要共用该视图。新注册军团只需建立身份角色和用户角色关系，无需复制菜单；已有军团自动读到同一份权限。

`MenuService.listByRoleId` 直接查询当前有效菜单，避免策略或套餐变化后路由缓存继续展示旧菜单。`SaExtensionInterceptor` 在 EVE 请求及 `/auth/user/info`、`/auth/user/route` 首屏请求之前刷新在线用户权限。

## 新功能开发约定

1. 在增量迁移中登记菜单和军团套餐菜单。
2. 在同一迁移中向 `eve_derived_role_menu` 登记允许的派生身份，同时包含页面所需父目录。
3. 所有已有军团和未来军团自动读取该定义；发布过程不枚举军团、不向各军团角色补写菜单。
4. 普通业务角色仍由军团管理者自行配置。撤销默认授权时修改全局定义，套餐移除菜单或禁用后也会实时限制派生权限。

完整迁移测试校验有效军团套餐菜单均有策略定义、每个身份的路由父目录完整；防止新增功能遗漏统一授权登记。
