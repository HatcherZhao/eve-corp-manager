# 军团人员模块：确认笔记

> 状态：讨论稿 v0.1（2026-09-08）  
> 规则：已确认项可作为实施约束；待确认项不可被默认为最终产品口径。

## 已确认

| 主题 | 结论 | 来源 |
| --- | --- | --- |
| 租户模型 | 一个游戏军团对应一个本站租户；成员只看所属军团信息 | 已确认产品方向 |
| 管理身份 | 游戏内 CEO 可授予总监；本站应以真实游戏权限派生身份，并允许管理本站业务角色 | 已确认产品方向 |
| 授权刷新 | 已授权用户可主动刷新权限，角色权限升级后可重新同步 | 已完成授权能力 |
| 权限展示 | 必须展示全部游戏权限及当前拥有权限 | 已完成权限树能力 |
| 隐私边界 | 个人数据不因 CEO / 总监授权而自动开放；游戏内写操作不由平台模拟执行 | 已确认边界 |
| 模块目标 | 下一业务模块为“军团人员”，作为后续资产信息、月矿情报、采矿贡献和游戏内邮件收件人的基础 | 本轮上下文 |
| 追踪数据展示 | 位置、舰船、登录/登出、基地不作为隐藏详情字段；拥有追踪查看权限的用户在成员名册即可查看 | 本轮确认 |
| 非总监权限 | 非总监可以被授予追踪查看权限 | 本轮确认 |
| 上下线语义 | 首版展示上游最近登录 / 登出记录，不标注实时在线或推算在线工时 | 本轮确认 |

## 本设计采用的口径

1. 名册以国服完整成员 ID 列表为唯一的“当前在团”判定来源；只有名册同步完整成功后才能发布新状态。
2. `start_date` 是官方成员追踪字段，不保证每次可用；不可用时，本站首次观察时间只能标注为“本站首次同步发现”，不能伪装成入团时间。
3. 位置、舰船、登录/登出、基地是可直接展示的运营追踪数据；必须单列本站权限，但拥有该权限的用户在成员名册即可查看，不要求总监身份。
4. 名字解析失败不阻塞名册事实入库；页面显示“待解析角色 ID”，同步任务继续补偿解析。
5. 角色、头衔、角色历史都保留“数据来源时间”和“上游缓存过期时间”；不承诺实时。
6. 角色 ID 是唯一业务标识；名称仅是可变化的展示字段。

## 待产品确认

| 编号 | 待确认点 | 默认建议 | 对设计的影响 |
| --- | --- | --- | --- |
| CFM-02 | 是否需要内部“分队 / 矿队 / 后勤”分组 | 需要，作为本站手工标签，不改游戏职位 | 标签表与成员列表筛选 |
| CFM-03 | 是否允许保存成员运营备注 | 允许；仅人员管理员可编辑，默认不对普通成员展示 | 备注表、审计、详情页权限 |
| CFM-04 | 角色变更历史保留多久 | 默认长期保留，支持按军团数据保留策略清理 | 分区 / 清理任务策略 |
| CFM-05 | 名册定时同步频率 | 自动同步以官方 `Expires` 为下限，默认不快于 60 分钟；手动同步在当前请求内执行，并保留权限校验和同资源互斥锁 | 调度与队列策略 |
