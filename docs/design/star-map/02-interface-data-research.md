# 星图与导航：接口与数据调研

> 依据：2026-09-16 下载的 [国服 Swagger](https://ali-esi.evepc.163.com/latest/swagger.json)。路径以 `/latest` 展示；实现时固定经真实验证的 `/vN` 路由版本。

| 官方接口 | 关键字段/结果 | 用途 | 授权 |
| --- | --- | --- | --- |
| `GET /universe/regions/`、`/{region_id}/` | 星域 ID、名称、星座列表 | 宇宙层级校验与补全 | 公开 |
| `GET /universe/constellations/`、`/{constellation_id}/` | 星座 ID、名称、所属星域、星系列表 | 宇宙层级校验与补全 | 公开 |
| `GET /universe/systems/`、`/{system_id}/` | 名称、星座、安全等级、`position(x,y,z)`、星门 ID 列表 | 星图节点、坐标和安全等级 | 公开 |
| `GET /universe/stargates/{stargate_id}/` | 所属星系、目的星系与星门、坐标 | 星图边和双向星门校验 | 公开 |
| `GET /route/{origin}/{destination}/` | 按顺序返回经过的星系 ID | 两点路线预览与保存时校验 | 公开 |

现有 `evedata.xlsx` 已持久化星域、星座、星系、空间站和公开建筑的中文名称及层级，适合作为显示名称基准；它不提供星图所需的三维坐标和星门连接，因此不能替代上述 Universe 数据。

## 同步策略

1. 先读取星系列表，向持久化任务写入待处理系统 ID；逐个读取星系详情，保存坐标、安全等级和待解析星门 ID。所属星域由已有星座静态资料关联得出。
2. 对去重后的星门 ID 续跑解析，保存来源/目的星系；同一对星系只输出一条无向图边。
3. 每个请求复用现有国服客户端的全局限速、`Expires`、退避和 Redis 互斥机制。进度、最近成功、失败数量和下次重试时间持久化，不因服务重启从头开始。
4. 首次建立索引后低频复核静态宇宙资料；路线请求按用户操作即时调用并短时缓存。官方返回异常时保留最后完整拓扑，页面明确展示资料时间。
