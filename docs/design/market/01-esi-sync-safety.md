# 官方市场同步安全与缓存

## 访问边界

- 用户浏览、列表翻页和估值只读取本地快照，不直接访问官方 ESI。
- 订单按区域分页抓取，再过滤到配置的吉他星系或空间站；成交历史明确为区域口径。
- 订单和历史任务各自持有 Redis 分布式锁，并在锁内检查共享的下次运行时间，防止多实例并发或错峰重复抓取。
- 所有真实 ESI 请求仍经过既有全局请求间隔。HTTP 420/429、`Retry-After` 及错误预算接近耗尽时会建立共享冷却；冷却只能延长，不能被后续成功响应提前解除。

## 缓存与发布

- 公开市场响应以完整 URL 为缓存维度，区域、物品和页码相互隔离。`Expires` 未到时直接复用；到期后发送 `If-None-Match`，304 复用原正文和分页信息。
- 即使分页后续失败或数据库落库失败，已经成功读取的响应仍可复用，不必提前重新抓取。原始响应缓存只额外保留一小时供 ETag 重验证，实际 Redis 占用应在部署后监控。
- 所有订单分页成功后才进入短数据库事务：批量合并本轮订单，显式写入空价格，并清空本轮消失物品的报价和订单。任意批次失败则整轮回滚，网络请求不占用事务。
- 订单、历史和访问时间分别更新各自字段，避免陈旧实体覆盖其他任务的最新数据。
- 历史单品的下次请求时间取本地一天周期与官方缓存期限的较晚值；失败物品延后重试，避免持续占据补温队列。

旧第三方历史原样保留，但不再按官方区域日均价展示；首轮官方历史同步成功后写入带区域 ID 的来源版本，页面才恢复展示。报价或订单同步不会覆盖这两个历史字段。

正常应用启动会执行新增迁移。发布前完成备份并确认 Redis 有足够容量；回退代码时可以保留这两个新增的可空列，不需要破坏性回滚表结构。
