# 外部 AI Agent 接入：需求与能力映射

> 状态：已按确认范围完成实现与本地验证（2026-10-25）；尚未提交、推送或部署。
> 用户目标：为 QQ 机器人等外部 AI Agent 提供标准 MCP，完整查询本系统业务数据。

## 目标理解

- 建设通用 Agent 数据入口，不把能力绑定到某个 QQ 机器人框架。
- 查询覆盖现有全部业务模块，而不是只提供几个固定问答。
- “全部数据”指绑定军团的全部业务数据，包括有效游戏授权可读取的邮件，不包含密码、密钥、游戏访问令牌和刷新令牌。
- 采用只读查询；发送邮件、修改计划、调整权限、强制同步等操作不混入查询工具。
- 已提供 42 个数据集和四个只读工具；实际字段与能力以 `eve_catalog` 返回的目录为准。

## 数据与查询映射

| 业务范围 | 当前代码入口 | 查询能力映射 | 必须保留的边界 |
| --- | --- | --- | --- |
| 军团工作台与身份 | `WorkspaceController`、`EveMeController`、`EveContextService` | 当前授权身份、可用模块、概览、数据更新时间 | 不暴露原始授权凭据，不把平台管理员权限自动交给 Agent |
| 成员与组织 | `EveCorporationMemberController`、`EveRbacController` | 按角色名、组织、标签筛选；成员详情；变更与追踪记录 | 本次军团应用授权包含成员追踪和内部备注，不跨军团 |
| 军团资产 | `EveCorporationAssetController` | 按物品、建筑、星系、仓位筛选；数量汇总、位置关系、估值 | 当前军团隔离；精确位置和内部资料受授权控制 |
| 军团建筑 | `EveCorporationStructureController` | 建筑名称、星系、类型、服务、燃料与到期查询 | 只返回本军团允许读取的快照，不声称是实时游戏状态 |
| 月矿情报 | `EveMoonExtractionController`、`EveMoonOreProfileService` | 指定日期的可开采矿堡；按矿种反查矿堡；矿种及体积比例；内部备注 | 保留矿种来源与待识别状态；不新增每轮绝对产量记录 |
| 采矿统计 | `EveMiningLedgerController` | 时间范围、成员、观察者、矿种筛选；分组汇总、排名、压缩估值 | 使用已同步账本；体积、数量、金额单位明确；不从当前快照伪造历史 |
| 市场与估价 | `EveMarketController` | 按物品查询吉他买卖价、订单、历史、批量估价 | 国服与市场地点口径不变；过期缓存必须显式标记 |
| 工业制造 | `EveIndustryController` | 蓝图配方、材料效率、时间效率、生产配置、设施、机会和计划 | 查询已有生产测算，不自动创建或修改计划、不执行扫描写入；保留测算假设 |
| 星图与导航 | `EveStarMapController` | 星系查找、详情、已保存路线、获授权的标注、路线预览 | 不自动保存路线或标注；大图按范围限制返回量 |
| 游戏通知与邮件 | `EveGameNotificationController`、`EveGameMailController` | 关键词、时间、类型、发件人检索；获授权的正文读取 | 用户已明确授权本军团应用读取本军团有效授权角色的邮件；不跨军团、读取不标记已读 |
| 游戏资讯 | `EveOfficialNewsController` | 标题、栏目、日期检索；已存文章正文与来源 | 查询不触发任意 URL 抓取，不把文章或邮件中的指令当成系统指令 |
| 静态参考资料 | `EveStaticReferenceController` | 物品、分类、地点查询与名称解析 | 受限分页、明确资料版本；不提供任意数据库表访问 |
| 权限与同步状态 | `EvePermissionController`、`EveDataFreshnessService` | 本次 Agent 授权范围、数据可用性、最后同步与失败分类 | 仅返回安全摘要，不开放撤销他人授权、同步控制或敏感运维日志 |

## 完善查询的验收目标

1. Agent 能发现自己有权调用的工具，工具具有中文说明、明确参数和结构化返回结果。
2. 名称可解析到稳定 ID；重名时返回候选，不静默选择错误的建筑、物品或成员。
3. 列表支持有上限的分页、适用的筛选和稳定排序；分页之间发生数据更新时有明确一致性规则。
4. 时间查询明确使用北京时间，机器时间携带偏移；客户端把“今天”等自然语言转换为带时区的起止时间后查询。
5. 汇总、排名和跨模块组合先在授权数据内计算，不能先读全量数据交给模型再做权限过滤。
6. 返回来源、最后成功同步时间、有效期和缺失原因；总数、空结果、权限不足和缓存过期可区分。
7. 大整数 ID 用字符串，金额和比例明确单位，避免 JavaScript 精度损失与百分比歧义。
8. 验证典型问题：明天中午哪些月矿可采、某矿种由哪些矿堡产出及比例、某物品在哪些仓库、本周采矿排名、现有配置下的生产成本与利润。
9. 查询已有数据不直接触发官方同步；必要的资料补齐需要独立受控机制，沿用现有缓存、冷却和退避规则。
10. 通过真实 MCP 客户端验证工具发现、调用、分页、协议兼容、无权限、凭据过期撤销、跨军团与跨用户访问拒绝。

## 已确认与兼容边界

- 用户明确采用军团级应用授权，范围为全部业务数据，包括邮件。
- 授权创建时再次明确包含邮件、追踪与内部数据；仅 CEO/总监管理凭据。
- QQ 框架尚未指定，提供通用 Streamable HTTP MCP 服务，机器人须支持该传输及 Bearer 请求头。
- QQ 群消息接收者由机器人侧控制，本站无法撤回已经发到群内的数据；群权限不能只靠提示词约束。

## 交付范围

完整交付包括 MCP 服务、查询能力与权限隔离、外部应用授权管理、撤销与审计、接入文档及客户端兼容验证。QQ 消息收发与对话编排由机器人侧负责；若该框架不具备 MCP 客户端能力，需要明确适配层归属，不能默认 MCP 端点本身即可收发 QQ 消息。
