# 外部 AI Agent 接入：确认笔记

> 状态：关键口径已确认，已完成实现与本地验证（2026-10-25）。本文不代表已部署或开放线上访问。

## 用户已明确的目标

- 系统具备对接外部 AI Agent 的能力。
- QQ 机器人是使用示例，接入方式希望采用标准 MCP。
- 支持本系统全部业务数据的完善查询。
- 授权主体按军团，不要求每位 QQ 用户绑定本站账号。
- 全部数据包括邮件；仅限本军团有效授权角色在系统中已有的邮件数据。
- 沿用既有约束：访问官方接口注意缓存、频率和爬虫规范，避免上游封禁。

## 采用的实现约束

- 默认仅查询，不附带发送邮件、修改数据或强制刷新的能力。
- 每个外部应用有独立凭据、授权范围、有效期、撤销和调用审计，不共用网页登录 Cookie。
- 授权固定绑定军团，包含该军团全部业务数据；不继承网页登录 Cookie，不允许调用者指定 tenantId 或 userId 提权。
- 采用远程 Streamable HTTP；使用成熟 MCP 实现，协议版本由目标客户端兼容性决定，不在讨论阶段锁定。
- 为通用客户端设计标准授权与发现；受控服务账号的凭据模式单独说明兼容边界，不把固定密钥等同于完整 OAuth 授权流程。
- 复用既有业务规则，补齐无副作用的查询路径，而不是提供任意 SQL 或任意 URL 代理。

## 当前代码事实与实现风险

| 事实 | 证据 | 对接时的要求 |
| --- | --- | --- |
| 本站使用 Sa-Token 会话、租户上下文和控制器权限注解 | `SaTokenConfiguration`、`SaExtensionInterceptor`、EVE 各控制器 | MCP 不能直接调用服务层就假定控制器权限仍生效；必须逐工具校验权限，并可靠建立和清除请求上下文 |
| 现有权限在线刷新主要针对 `/eve/` 路径 | `SaExtensionInterceptor.isEveRequest` | 新 MCP 路径须有独立有效权限校验，不能继续使用用户被撤销前的旧权限 |
| 成员追踪信息独立于基础名册授权 | `EveCorporationMemberService.hasTrackingPermission` | 搜索、详情、汇总及导出都遵守字段权限，不只控制页面显示 |
| 读取邮件详情会按需拉取正文，并在授权允许时标记已读 | `EveGameMailService.detail`、`markReadWhenAuthorized` | 新增真正只读的正文查询，不能把现有详情方法直接标成只读 MCP 工具 |
| 月矿列表会初始化矿种档案 | `EveMoonExtractionService.page`、`initializeOreProfiles` | Agent 高频查询不能重复触发初始化；矿种补齐与只读查询分离，缺失时返回待识别 |
| 市场详情读取本地快照并记录近期使用，不在请求内访问 ESI | `EveMarketService.detail`、`touch` | 维持后台限流同步机制；关注 Agent 批量查询对补温队列的影响，不把读取等同于强制更新 |
| 大部分现有列表已具备分页，但查询条件不等于目标完整能力 | 各 EVE 控制器的 `page`、工业列表接口 | 按能力映射补充时间、实体、分组和分页边界，不能宣称原样包装即可满足全部查询 |

## 安全设计边界

- 外部传入的 `tenantId`、`userId`、QQ 昵称或群号不构成授权证明；绑定关系与身份来自可信认证链路。
- 身份凭据逐请求验证；会话 ID、分页游标和资源句柄都不能替代身份认证。
- 邮件正文、通知、备注、文章都是不可信业务内容；结果明确为数据，不接受其要求提权、调用其他工具或泄露凭据。
- 审计记录工具、身份、授权范围、耗时、结果数量与成功状态，不记录密钥、查询参数或私人邮件正文。
- 限制单次结果、查询时间跨度、排序字段、并发与超时；聚合和计数同样先应用权限条件。
- MCP 无法独自验证 QQ 消息将发往哪里。若开放群聊，需要可信适配层与群可公开范围；不能给机器人管理员凭据后仅靠提示词约束。
