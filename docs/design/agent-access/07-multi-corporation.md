# 一个应用对接多个军团

## 已确认需求与操作

2026-10-26 用户确认采用一个 Agent、一个 MCP 连接和一个密钥，由各军团 CEO／总监独立批准的方式。Agent 是现有 AstrBot 等外部客户端，本站不创建机器人，也不主动连接机器人。

| 操作者 | 操作 | 服务端边界 |
| --- | --- | --- |
| 机器人登记方 | 登记应用、配置一次 MCP、复制授权链接 | 沿用本站已验证的管理身份，不新增匿名应用注册 |
| 目标军团 CEO／总监 | 登录链接，核对应用与本军团，明确确认包含邮件后批准 | 军团与租户来自实时站内身份，不能由链接或请求指定 |
| 目标军团 CEO／总监 | 撤销本军团授权 | 不撤销应用密钥，不影响其他军团 |
| 应用登记方 | 更换密钥或停用整个应用 | 停用会同时阻止该应用访问所有已授权军团，界面必须明确提示 |
| QQ 玩家 | 查询默认军团，或在允许跨军团的会话指定军团 | 机器人可信代码校验真实会话来源，提示词和技能不是权限边界 |

没有默认军团且存在多个候选时不猜测。网站仅知道应用及其军团授权，不知道 QQ 发言者身份；多人使用同一应用必须配套机器人侧会话授权。

## 数据与授权设计

- 保留既有应用记录及密钥摘要，登记方军团仍管理该应用；独立军团授权存入新的授权表。
- 追加迁移，为旧应用保留原军团授权，原密钥无需重新录入。不修改已执行的变更集。
- 分享代码不是调用密钥，仅用于定位待批准的应用。打开链接、预览和登录都不会自动授予权限。
- 新授权需要明确确认军团全部只读业务数据包含已授权角色邮件。游戏角色的有效授权、Scope 和现有数据集隔离规则继续生效。
- 应用有效期、应用停用、军团绑定状态和单团授权状态在每次请求中重新校验。单团撤销不能由应用登记方擅自恢复。
- 凭据只返回一次，不进入浏览器持久化存储、技能包、分享链接、日志或测试样本。
- 授权审计落在目标军团；应用级发现事件落在登记方军团。不得将另一个军团的调用误记成登记方业务查询。

## MCP 查询契约

- 新增 `eve_corporations`，返回当前应用有效授权的 `corporationId`、名称和简称，不返回租户内部 ID。
- `eve_catalog`、`eve_query`、`eve_aggregate`、`eve_read_document` 新增字符串参数 `corporationId`。仅唯一有效军团时允许省略；多个军团时必须明确指定。
- 认证得到应用身份，查询前根据有效授权解析目标军团身份。客户端参数只用于选择已经授权的军团，不能直接成为 SQL 租户边界。
- 四个查询工具结果携带实际使用的 `corporationId`，便于客户端核对范围。正文后续分段与翻页沿用同一个军团。
- 所有查询仍只访问本站缓存，不因增加军团或玩家查询而触发官方接口抓取。

## QQ 会话权限

提供 AstrBot 配套插件／可信适配层，按真实平台会话标识配置默认军团和允许军团。未配置会话默认拒绝。单团会话注入默认军团，管理会话允许从白名单选择；军团发现结果也必须过滤。不得仅给模型一份群与军团对应提示词。

插件接入必须避免仍可直接调用未受保护的原始 MCP 工具的旁路。实际采用方式及已验证的 AstrBot 接口、安装步骤记录在插件目录说明中。未进行生产部署或真实 QQ 验收前，不称为已上线。

## 验收

1. 原应用密钥继续访问原军团；迁移不意外扩大原应用权限。
2. 同一应用获两团批准后可分别查询，省略军团报明确错误；未授权军团及伪造租户参数不能访问。
3. 本团撤销立即阻止后续查询，不影响另一团；应用停用、到期和密钥轮换继续有效。
4. 邀请访问不授权，非管理者不能批准，跨团管理操作不能轮换或停用别团登记的应用。
5. 邮件正文、统计、分页与并发请求保持目标军团隔离，审计失败不返回数据。
6. 页面完成登记、复制链接、登录回跳、批准与单团撤销，验证桌面和窄屏的加载、错误与确认状态。
7. QQ 适配层测试默认注入、跨团拒绝、未知来源拒绝、发现过滤及并发隔离，不使用真实密钥或军团资料。
