# 工业制造模块：实施计划

> 文档状态：实施基线（2026-09-28）  
> 适用范围：EVE 国服 Serenity、吉他贸易中心吉他海军第四空间站、工业制造与市场机会分析模块  
> 关联文档：[需求映射](./00-requirements-mapping.md)、[确认笔记](./01-confirmation-notes.md)、[功能详细设计](./03-functional-detailed-design.md)、[数据库设计](./04-database-design.md)、[页面信息架构](./08-industry-page-information-architecture.md)

## 1. 实施目标

把当前已经落地的“工业计算 + 机会分析 + 配置与数据校验页面”继续实施为可复盘、可生成计划、可跟踪执行的完整工业能力。

最终用户应能完成以下闭环：

```text
配置生产条件
  → 导入并校验国服蓝图
  → 刷新吉他订单与市场历史、生产星系 SCI
  → 扫描有利润且有市场承接能力的机会
  → 查看材料逐档采购与费用依据
  → 固化为生产计划
  → 按批次采购、生产、销售和风险状态跟踪
```

本计划不改变已经确认的业务口径：

- 只支持国服 Serenity；
- 材料采购和产品销售固定参考吉他海军第四空间站；
- 每次视为没有库存，材料全部按市场购买；
- 不计算运输成本；
- 不计算蓝图购置、摊销或机会成本；
- 蓝图 ME、TE、BPO/BPC 和剩余流程数可配置；
- 生产地点、建筑、服务、Rig、安等、设施税和附加费可人工选择并保存；
- 普通制造、反应和“蓝图已就绪”的 T2 制造进入正式机会范围；复制、发明、逆向工程首阶段只展示前置活动，不将其成本和工时混入正式利润。

## 3. 实施原则与不变规则

### 3.1 数据分层

静态主数据、外部事实快照、租户配置、计算结果和计划快照必须分层保存：

```text
静态蓝图/规则
  + 国服市场订单与历史
  + 星系 SCI/安等/设施事实
  + 军团配置与蓝图研究覆盖
  → 版本化计算上下文
  → 机会快照
  → 生产计划快照
```

任何刷新都不得覆盖已被计划引用的旧计算上下文。

### 3.2 数量与单位

- `R` 表示蓝图活动流程数；`Q` 表示最终产物件数；`q` 表示单流程产物数。
- 只在边界执行一次 `R = ceil(Q / q)`，禁止把产物件数再次当作流程数。
- 材料数量按整份 job 计算并向上取整；最终精度和例外以国服 Golden Case 固化。
- 金额使用 `decimal(20,2)`；数量使用整数；时间统一使用秒。

### 3.3 可执行状态

| 状态 | 允许条件 | 可进入正式计划 |
| --- | --- | --- |
| `EXECUTABLE` / 可执行 | 国服配方已验证、活动资格成立、市场/SCI/设施关键输入完整且在新鲜度门槛内 | 是 |
| `TRIAL` / 可试算 | 使用回退配方、过期行情、估算税率或缺少非关键输入 | 否，必须显式转为可执行 |
| `UNAVAILABLE` / 不可执行 | 活动不在支持范围、关键数据缺失、订单深度或历史销量无法支撑 | 否 |

## 4. 工作包与实施顺序

以下顺序是依赖顺序，不代表拆成互相割裂的产品版本。每个工作包完成后都要补测试、文档和验收证据。

### WP-01：实施基线与权限校准

**目标**：冻结当前代码和数据口径，消除文档、菜单和接口权限的不一致。

**任务**：

1. 以 049 为最后一个菜单迁移基线，禁止修改已执行的 047/048/049 changeset。
2. 对照实际 `sys_menu`、Controller 注解和页面路由，统一六个页面的标题、路径、组件名和权限。
3. 决定是否保留细粒度权限：`view`、`config:manage`、`data:manage`、`plan:manage`；若暂不启用细粒度计划权限，必须在权限矩阵中记录兼容策略。
4. 为每个接口补 OpenAPI 说明、请求示例、错误码和数据来源说明。

**交付物**：权限矩阵、接口目录、实施基线记录。  
**完成标准**：页面菜单、前端访问控制、后端 `SaCheckPermission` 和设计文档一致。

### WP-02：国服静态蓝图与规则可信度

**目标**：让进入正式榜单的配方具备可追溯来源和国服校验依据。

**任务**：

1. 固化 `SERENITY_EXPORT`、`CEVE_INDUSTRY_PUBLIC`、`TRANQUILITY_SDE` 三类来源状态机。
2. 同步时保存 `server_version`、构建号、下载时间、SHA-256、schema 版本和导入错误摘要。
3. 为蓝图活动补齐活动资格、产品可交易性、技能/设施要求和 BPO/BPC 关系字段；现有 JSON 字段不足时新增 050 以后迁移或子表。
4. 将 ceve-industry.cn 规则作为默认实现依据，但把第三方来源与国服验证状态分开保存。
5. 建立 Golden Case 导入模板、校验报告和失败阻断：材料、时间、概率、设施加成存在差异时，标记版本待确认，不静默覆盖。
6. 国服 `server_version` 变化时，将相关蓝图标记为 `PENDING_REVALIDATION`，禁止自动进入正式榜单。

**交付物**：可追溯静态版本、蓝图校验报告、Golden Case 回归集。  
**完成标准**：任一正式机会都能反查到静态版本、来源、校验状态和适用规则版本。

### WP-03：市场、SCI 与设施事实快照

**目标**：保证成本、收入和“有市场”判断使用同一时间边界的数据。

**任务**：

1. 复用 `eve_market_snapshot` 获取吉他海四订单与历史，增加按计算批次固化的市场输入快照。
2. 为材料采购和成品销售保存实际使用的订单档位切片：方向、价格、数量、累计数量和来源时间。
3. 读取国服 `/industry/systems/`、`/universe/systems/{id}` 和设施/Dogma 数据，保存星系 SCI、安等、服务能力和更新时间。
4. 明确人工设施配置与 ESI 事实的优先级：人工覆盖必须记录操作者、确认时间和原因；自动刷新不能覆盖人工覆盖。
5. 为市场报价、历史成交、SCI 和国服状态分别设置 TTL；过期数据只能产生 `TRIAL`，不能伪装为实时事实。

**建议新增表**：

- `eve_industry_market_input_snapshot`
- `eve_industry_market_order_slice`
- `eve_industry_system_snapshot`

**完成标准**：打开机会详情时可以解释材料成本、买单收入、挂单收入、SCI 和数据时间点。

### WP-04：计算引擎统一与回归锁定

**目标**：让单蓝图计算、机会扫描和后续计划共用同一套纯计算规则。

**任务**：

1. 将 `EveIndustryCalculator` 拆分为材料、时间、EIV/安装费、市场订单填充、需求约束、评分和状态判定等可测试单元。
2. 统一 `R/Q/q` 语义，禁止 API、扫描器和计划器分别解释流程数。
3. 固化材料、时间、设施倍率、SCI、设施税、版本化附加费和市场费用的计算顺序。
4. 材料采购从最低卖单逐档填充；订单深度不足时记录缺口，不向最后一档价格无限外推。
5. 立即变现按最高买单逐档填充；挂单收入扣除经纪费和销售税，并标识为预期收入。
6. 以 `30 日平均成交量 × 目标天数 × 市场占比上限` 为安全可消化产量基线，再结合 7 日趋势、波动和订单深度修正。
7. 把规则版本、权重版本、假设标签写入计算结果。

**完成标准**：同一输入在单张蓝图、机会扫描和计划预览中得到一致结果；所有公式均有单元测试和至少一个 Golden Case。

### WP-05：机会分析生产化

**目标**：从手工扫描扩展为可持续、可解释的机会榜单。

**任务**：

1. 扫描前校验静态版本、设施资格、SCI、市场报价和新鲜度门槛。
2. 生成机会快照时写入配置版本、设施版本、蓝图覆盖、市场/SCI 输入快照和风险标签。
3. 计算立即变现榜、挂单销售榜、利润率、每线小时利润、每日可实现利润、资金占用、预计售罄时间和综合评分。
4. 每日生成一次全量机会快照；保留用户手工扫描，二者使用同一服务入口和规则版本。
5. 对市场深度不足、历史销量不足、配方未验证、SCI 缺失、TQ 回退等情况分别展示风险，不合并成模糊的“数据异常”。
6. 增加“重新计算”与“加入计划”动作，加入计划时固化当前机会快照，而不是重新读取最新行情。

**完成标准**：榜单排序可以解释；同一快照重复打开结果不变；市场刷新后旧结果保留并显示“有更新”。

### WP-06：生产计划与 DAG

**目标**：把可执行机会固化为带材料、工序和来源快照的计划。

**任务**：

1. 新增计划主表，保存计划名称、来源机会、配置/设施/蓝图/市场/SCI/规则版本、目标产量、总投入、预计收入、利润、状态和风险。
2. 新增计划步骤表，统一表达材料采购、复制/发明前置展示、生产批次和销售跟踪步骤。
3. 首阶段计划按“材料全部外购”的口径生成，不递归展开自产中间件；DAG 结构要能承载未来扩展。
4. 支持从机会创建草稿、人工覆盖批量、重新计算草稿、确认计划、复制旧计划和归档计划。
5. 计划状态至少支持：草稿、已确认、采购中、生产中、可交付、已交付、已取消。
6. 计划详情展示理论计划与当前执行状态的差异，但不自动提交游戏内制造或市场订单。

**建议新增表**：

- `eve_industry_plan`
- `eve_industry_plan_step`
- 后续按需要增加 `eve_industry_plan_material`、`eve_industry_plan_event`

**建议接口**：

```text
GET    /eve/industry/plans
POST   /eve/industry/plans
GET    /eve/industry/plans/{id}
POST   /eve/industry/plans/{id}/recalculate
POST   /eve/industry/plans/{id}/copy
PUT    /eve/industry/plans/{id}/status
GET    /eve/industry/plans/{id}/materials
GET    /eve/industry/plans/{id}/steps
```

**当前状态**：已落地从 `EXECUTABLE` 机会创建草稿、`PURCHASE → PRODUCTION → SALES` 步骤 DAG、状态更新、复制和来源快照固化。库存仍固定为 `MARKET_ONLY`，不自动执行游戏内操作。

**完成标准**：计划可以脱离最新市场数据复盘；计划引用的机会和订单档位不会被刷新任务删除或覆盖。

### WP-07：库存与材料模式

**目标**：在不改变当前默认口径的前提下，接入可选库存来源。

**任务**：

1. 先将“无库存、全部市场购买”定义为明确的 `inventoryMode=MARKET_ONLY`，写入配置和计算快照。
2. 增加人工库存录入/导入，记录物品、数量、位置、所有权、有效期和来源。
3. 增加 ESI 军团资产读取和同步状态展示；没有授权或数据过期时不得影响默认市场购买模式。
4. 增加库存覆盖开关，并在计算结果中同时展示市场原始成本、库存抵扣数量和剩余采购成本。
5. 库存被计划占用后，必须记录占用量，防止多个计划重复使用同一库存。

**完成标准**：未启用库存时结果与当前实现完全一致；启用后每一件抵扣材料都能追溯来源和占用关系。

### WP-08：前端页面从骨架到闭环

**目标**：让六个页面形成一致的发现、核算、计划、数据维护体验。

**任务**：

1. 机会分析增加“加入计划”、快照时间、数据更新提示和重新计算确认。
2. 蓝图计算增加当前计算上下文摘要、假设标签、来源时间和导出/复制入口。
3. 生产计划页接入列表、详情、材料采购、步骤 DAG、状态更新和复制计划。
4. 库存与材料页接入库存来源、占用关系、材料缺口和市场采购明细；默认仍显示市场购买口径。
5. 工业配置页补充配置复制、启停、版本差异和设施覆盖说明。
6. 数据与校验页增加版本状态机、导入错误定位、Golden Case 对比、来源新鲜度和重新验证动作。
7. 保持 320px 至桌面宽度适配：机会表移动端卡片化，材料和订单档位保留横向滚动，计划 DAG 可缩放。

**完成标准**：用户不需要记住后端接口；每个金额、数量、风险和状态都能在页面内找到解释来源。

### WP-09：调度、监控与运维

**目标**：让动态数据刷新和失败恢复可观测、可重试、可审计。

**任务**：

1. 增加市场订单短 TTL 刷新、市场历史刷新、SCI/系统事实刷新和每日全量机会扫描任务。
2. 记录任务开始时间、来源、请求批次、成功数量、失败数量、失败摘要和下一次重试时间。
3. 当上游失败时保留最近一次成功快照，并将页面状态标为过期/不可执行，而不是清空旧结果。
4. 为静态数据、市场、SCI、设施和计划执行分别提供健康状态指标。
5. 对大批量蓝图扫描做分页、批处理和限流，避免单次请求占满数据库或上游接口配额。

**完成标准**：任何一次自动刷新失败都能在数据与校验页定位；恢复后不会重复生成相同快照或覆盖计划历史。

### WP-10：质量验证与上线验收

**目标**：用计算、数据、权限、页面和回归证据证明工业模块可用。

**任务**：

1. 单元测试：材料向上取整、ME/TE、流程/产物转换、订单逐档填充、EIV/安装费、需求限制、评分和状态。
2. 集成测试：静态导入、ceve 同步、SCI 同步、市场快照、计划保存与快照引用、权限拒绝。
3. 数据测试：至少覆盖普通制造、反应、BPC 剩余流程、订单深度不足、无历史成交、SCI 缺失、T2 蓝图已就绪假设。
4. 前端测试：六个页面的加载/空状态/错误状态/跳转/抽屉/表单和移动端布局。
5. 端到端验收：从配置 → 同步 → 扫描 → 查看机会 → 加入计划 → 查看材料和步骤完整走通。
6. 对生产环境只执行新增 Liquibase changeset，禁止修改或重放已执行迁移。

cd ../backend

## 7. 关键风险与决策门

| 风险 | 触发条件 | 处理方式 |
| --- | --- | --- |
| 国服静态配方未获得完整正式导出 | 只有第三方公开数据或 TQ 回退 | 允许试算，标记来源；禁止进入正式可执行榜单，直到 Golden Case/版本校验通过 |
| 国服设施税/附加费规则变化 | Golden Case 与当前公式持续偏差 | 版本化 `versionedSurcharge` 和规则参数，不硬编码国际服 SCC |
| 市场历史只有星域口径 | 无法取得吉他站级成交历史 | 页面明确标注星域口径；用订单深度限制批量，不把历史销量伪装成空间站销量 |
| ESI 授权失效 | 资产/建筑接口不可用 | 保留最近成功快照，回退 `MARKET_ONLY`，不阻断基础机会分析 |
| 计划数据模型扩张 | 需要自产中间件、多产品、发明链或真正执行任务 | 通过计划步骤/DAG 扩展，不在机会表中塞入隐式递归字段 |
| 旧菜单权限已被用户使用 | 细粒度权限迁移会隐藏页面 | 先兼容 `eve:industry:view`，新增权限只扩大管理能力，不收回已有查看权限 |

## 8. 完成定义

工业制造模块达到本计划完成定义时，必须同时满足：

1. 六个页面均有真实后端能力或明确的只读空状态，不出现伪造计划、库存或执行进度。
2. 任一机会和计划都能追溯静态蓝图、市场订单、市场历史、SCI、设施、配置和规则版本。
3. 单张蓝图、机会扫描和计划预览使用同一计算引擎，输入一致时结果一致。
4. 正式计划不会因后续行情刷新而被覆盖；刷新只产生新快照并提示差异。
5. 市场不足、配方未验证、SCI 缺失、数据过期等情况有可读风险解释，并且不会悄悄进入正式榜单。
6. 生产计划能够保存批次、材料、工时、费用、销量假设、风险和步骤状态，但不自动执行游戏内操作。
7. 前端、后端、数据库迁移、权限、测试和运维文档同步更新，并有可重复的验证命令。
