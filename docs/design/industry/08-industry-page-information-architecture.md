# 工业制造模块：页面信息架构与菜单设计

状态：设计确认稿（2026-09-28）

## 1. 设计目标

工业模块面向三类人：

- **工业规划人员**：寻找利润高、市场能承接的产品，并生成生产计划；
- **生产执行人员**：按计划采购材料、跟踪工序和交付状态；
- **工业管理员**：维护蓝图、设施、技能、市场费用和数据校验规则。

页面组织围绕四个动词展开：**发现机会、核算方案、安排生产、维护依据**。菜单只暴露稳定的工作入口，产品详情、材料明细、价格档位、风险解释和计算快照放在页面内的抽屉/侧栏，不单独制造大量菜单项。

## 2. 一级菜单建议

```text
EVE 军团管理
├─ 军团工作台                         /eve/workspace
├─ 成员与权限                         /eve/members
├─ 资产与建筑                         /eve/assets、/eve/structures
├─ 市场与资源                         /eve/market、/eve/mineral-prices
├─ 工业制造                           /eve/industry
├─ 采矿与月矿                         /eve/extractions、/eve/mining
├─ 游戏通信                           /eve/mail、/eve/notifications
└─ 星图与参考                         /eve/starmap、/eve/reference/types、/eve/reference/locations
```

工业制造作为独立一级模块，原因是它同时连接市场、蓝图、设施、资产和生产任务；如果继续把它挂在“市场”或“资产”下面，用户会误以为工业只是价格查询或资产查看功能。

## 3. 工业制造二级菜单

建议把工业目录拆成六个稳定入口：

```text
工业制造
├─ 机会分析                           /eve/industry/opportunities
├─ 蓝图计算                           /eve/industry/calculator
├─ 生产计划                           /eve/industry/plans
├─ 库存与材料                         /eve/industry/inventory
├─ 工业配置                           /eve/industry/config
└─ 数据与校验                         /eve/industry/data
```

### 3.1 机会分析：默认落地页

页面类型：dashboard/report + CRUD/list，视觉权重为平衡但以表格为主。

用途：回答“现在生产什么最值得做，而且市场能吃下多少”。

页面结构：

```text
页面头部
├─ 当前市场口径：吉他海军第四空间站
├─ 当前生产配置 / 生产设施
├─ 数据新鲜度与风险提示
└─ 扫描机会、刷新行情、导出结果

摘要条
├─ 可执行机会数
├─ 立即变现最高日利润
├─ 挂单销售最高日利润
├─ 平均资金占用
└─ 订单深度不足数量

筛选区
├─ 活动：制造 / 反应 / T2 假设
├─ 产品分类、名称
├─ 生产配置、生产设施
├─ 机会状态：可执行 / 可试算 / 不可执行
├─ 排序：日可实现利润 / 利润率 / 资金占用 / 流动性 / 风险
└─ 只看有订单、只看有历史成交

主表格
├─ 产品与蓝图
├─ 推荐流程数 / 产量
├─ 材料成本、安装费、总投入
├─ 买单立即利润
├─ 挂单预期利润
├─ 可实现日产量、预计售罄天数
├─ 流动性与风险标签
└─ 操作：查看详情、加入计划、重新试算
```

交互规则：

- 表格行点击打开“机会详情抽屉”，不跳出当前列表；
- 详情抽屉固定展示：利润结论、材料采购明细、逐档订单、工时、SCI、费用、销量依据和风险解释；
- “加入计划”将当前计算快照转为生产计划草稿；
- 扫描结果按 `scanId` 固定，市场更新只显示“可重新计算”提示，不覆盖旧结果；
- 移动端将表格切换为机会卡片，卡片只保留产品、日利润、投入、市场承接和主操作。

### 3.2 蓝图计算：主动试算入口

页面类型：workspace/detail。

用途：对单张蓝图进行精确试算，适合核对材料、时间和价格，不承担全量排行。

页面采用“左侧输入、右侧结果”的工作台结构：

```text
左侧：试算条件
├─ 产品 / 蓝图
├─ 目标产物数量或流程数
├─ BPO / BPC、剩余流程
├─ ME / TE
├─ 生产配置
├─ 生产设施、星系、建筑、Rig
├─ 销售方式：立即买单 / 挂单
└─ 重新计算

右侧：试算结果
├─ 产物、工时、材料总量
├─ 材料逐档采购成本
├─ EIV、SCI、设施费、SCC、市场费
├─ 立即收入/利润
├─ 挂单收入/利润
├─ 单件成本、利润率、资金占用
└─ 公式展开与告警
```

不在菜单中单独提供“材料明细”“公式明细”“订单明细”页面，全部作为结果页的可展开区域。

### 3.3 生产计划：从机会到行动

页面类型：workspace/detail + CRUD/list。

用途：把一个或多个生产机会固化为可执行计划，并查看材料采购和工序状态。

页面分为列表和详情两个层次：

```text
计划列表
├─ 草稿 / 执行中 / 已完成 / 已归档
├─ 计划名称、产品数、总投入、预计利润
├─ 计划周期、生产设施、创建人、快照时间
└─ 打开、复制、重新计算、归档

计划详情
├─ 计划摘要：目标产量、投入、利润、工期、风险
├─ 物料采购：缺口、数量、单价、预计金额
├─ 工序 DAG：前置材料 → 中间品 → 最终产品
├─ 生产线排程：每条线的流程、开始/结束时间
├─ 工业任务关联：未启动 / 生产中 / 可交付 / 已交付
└─ 固定计算快照与重新计算入口
```

计划详情允许横向查看“理论计划”和“当前执行状态”，但不在本阶段自动提交游戏内任务或市场订单。

### 3.4 库存与材料：显式覆盖模式

页面类型：CRUD/list + workspace/detail。

默认状态为“无库存”，不能因为存在资产数据就自动降低材料成本。

页面分为三个页签：

- **材料清单**：按计划汇总采购材料、数量、预计金额、订单深度和采购状态；
- **人工库存**：手工维护可用数量，默认关闭“参与计算”；
- **ESI 资产与任务**：显示个人/军团资产和工业任务来源，用户明确勾选位置后才允许作为库存覆盖。

页面顶部必须有醒目的库存模式开关：

```text
当前计算口径：不计库存，全部按市场购买
[启用库存覆盖] 说明：启用后会改变材料成本、采购量和计划依赖
```

资产估价、化矿建议可以从该页面的物品行打开抽屉，不作为工业主菜单的一级页面；当相关能力成熟后，再作为“市场与资源”下的独立入口。

### 3.5 工业配置：面向管理员的配置中心

页面类型：CRUD/list + form/wizard。

建议使用页签，而不是继续在生产机会页堆叠弹窗：

```text
工业配置
├─ 生产配置
│  ├─ 固定角色技能等级
│  ├─ 制造/反应生产线数
│  ├─ 市场税率、经纪费率
│  ├─ 目标周期、市场占比上限
│  └─ 数据新鲜度门槛
├─ 生产设施
│  ├─ 实际/假设地点
│  ├─ 星系、安等、建筑、在线服务
│  ├─ Rig、材料/时间/成本倍率
│  ├─ 制造/反应 SCI
│  ├─ 设施税、版本化附加费
│  └─ 生产线能力
├─ 蓝图配置
│  ├─ BPO/BPC
│  ├─ ME/TE
│  ├─ BPC 剩余流程
│  └─ 来源与版本
└─ 市场规则
   ├─ 固定市场地点（只读：吉他海四）
   ├─ 采购/销售策略
   ├─ 买单深度和挂单价格策略
   └─ 运输费（当前固定为 0，保留展示）
```

保存策略：配置使用版本号；已被机会或计划引用的配置不物理删除，只能停用或复制新版本。

### 3.6 数据与校验：工业数据治理

页面类型：CRUD/list + workspace/detail。

只有工业管理员和系统管理员可见。

```text
数据与校验
├─ 数据总览
│  ├─ 最新蓝图批次
│  ├─ 市场行情新鲜度
│  ├─ SCI 新鲜度
│  ├─ 可执行/可试算/不可执行数量
│  └─ 最近同步失败
├─ 蓝图数据版本
│  ├─ CEVE 公开同步批次
│  ├─ 国服静态导入批次
│  ├─ SHA-256、来源、版本、导入时间
│  └─ 版本差异
├─ Golden Case
│  ├─ 游戏内样例
│  ├─ 材料/时间/安装费对账
│  ├─ PASSED / FAILED
│  └─ 差异详情
└─ 同步日志
   ├─ 市场订单与历史
   ├─ adjusted price
   ├─ 星系 SCI
   └─ 失败原因与重试
```

## 4. 页面之间的用户路径

### 路径 A：寻找高利润产品

```text
机会分析 → 调整生产配置/设施 → 扫描 → 筛选可执行机会
        → 查看机会详情 → 对比买单/挂单 → 加入生产计划
```

### 路径 B：验证一张蓝图

```text
蓝图计算 → 选择蓝图与 ME/TE → 选择设施 → 计算
        → 查看材料逐档采购 → 对照游戏内任务 → 记录 Golden Case
```

### 路径 C：执行生产计划

```text
生产计划 → 打开计划 → 采购材料 → 查看工序 DAG
        → 记录工业任务进度 → 交付 → 归档快照
```

### 路径 D：管理员更新计算依据

```text
数据与校验 → 同步/导入蓝图 → 刷新市场与 SCI
        → 运行 Golden Case → 工业配置 → 重新扫描机会
```

## 6. 视觉与交互组织原则

### 6.1 领域化的界面签名

- **领域概念**：蓝图、流程、订单簿、SCI、生产线、可消化产量、计算快照；
- **色彩语义**：深色中性底为工作台，蓝色表示配置/数据，绿色表示可执行利润，橙色表示可试算与订单风险，红色表示不可执行；
- **唯一签名**：机会详情中的“利润瀑布”——销售收入 → 市场费用 → 安装费 → 材料采购 → 净利润，并在旁边显示订单深度和预计售罄时间；
- **密度**：机会表和材料表采用紧凑密度，配置表单采用中等密度，计划 DAG 采用可缩放的工作区；
- **表面策略**：沿用现有 Arco Design 和项目主题变量，采用低对比边界与状态色，不为工业模块另建一套视觉主题。

### 6.2 页面共同布局

所有工业页面统一使用：

```text
页面容器
├─ 紧凑页面标题：当前位置、口径、主操作
├─ 数据新鲜度/假设提示条
├─ 页面摘要或表单条件区
├─ 主工作区
└─ 详情抽屉 / 侧边检查器
```

不使用大型营销式 Hero；工业页面的重点是比较、筛选和操作，表格或工作区必须在首屏占据主要面积。

### 6.3 响应式规则

- 320–767px：一级菜单变为抽屉；工业二级菜单变为顶部横向滚动 Tab；机会表切换为卡片；详情抽屉改为底部抽屉；
- 768–1199px：保留表格核心列，次要列进入“更多信息”；筛选条件允许折叠；
- 1200px 以上：机会分析使用全宽表格，右侧机会详情使用抽屉，不挤压主表；蓝图计算保留双栏工作台；
- 所有表格必须允许自身横向滚动，不允许页面根节点产生横向溢出；
- 主操作触控区域不小于 40–44px，数字列使用等宽数字，金额与数量右对齐。

## 8. 首屏默认状态

用户进入“机会分析”时，页面必须直接显示可理解的状态：

- 已选择的生产配置和设施；
- 市场口径固定为“吉他海军第四空间站”；
- 最近市场、SCI、蓝图数据时间；
- 当前是否按无库存计算；
- 最近一次扫描结果或“尚未扫描”的空状态；
- 当数据不完整时，明确显示“可试算”而不是展示看似精确的利润。

空状态必须提供下一步按钮：

```text
没有可执行机会
→ 配置生产设施
→ 同步公开蓝图
→ 刷新吉他行情
→ 运行一次机会扫描
```
